# Moon Base v2

Created: 2026-09-26
Status: draft. Slice 1 (hook-free live status) and easy start (R2) were promoted into `docs/features/moon-base/spec.md` on 2026-09-26 as AC14 and AC15. Slices 2 to 4 are not specified yet.

## Problem

v1 is a good viewer, and with the terminal hand-off it is also a launcher. At work, where sessions are Claude Code CLI in cmux, with no desktop app and no access to Claude hooks, it falls short:

- Status is inferred from session files, so it lags, and there is no "waiting on you" signal.
- A bot's card shows a title and the first prompt, nothing about what the agent last said or asked.
- CLI sessions carry no PR information.
- Starting it means `npm run dev` from a cmux terminal, and diagnosing "why no bot?" or "why not live?" meant reading process lists and JSON by hand (see the M6 run in `docs/features/moon-base/plan.md`).

## Users / Actors

- **A1. The developer at work.** Several Claude Code CLI sessions in cmux across repos. No desktop app, no usable Moon Base hooks. cmux itself does show agent status there (confirmed 2026-09-26), so its own hooks fire.
- **A2. The same developer on a personal machine.** Desktop apps and Moon Base's own hooks. The v1 path stays as it is.

## Goals, in order

- **G1. Live status at work, hook-free** (slice 1).
- **G2. Attention:** one cross-repo view of what is waiting on you (slice 2).
- **G3. Insight:** what a session last said or asked, a "today" timeline, and a PR link for CLI sessions (slice 3).
- **G4. Reach and polish:** a doctor command, easy start, and sound, mascot and planet polish (slice 4). Always-on start was dropped on 2026-09-26.

## Sequencing

G1 comes first because it is the shared foundation: G2 and the last-said card in G3 both need a trustworthy "what state is this session in, and since when" feed. G4's doctor command should land early, since it is how slice 1 gets verified at work. Easy start is independent of the rest and shortens every later test at work, so it is a good early companion. Sound, mascot and planet polish is independent and taste-driven, so it fills gaps.

## Slice 1. Hook-free live status (F1)

### What was found (2026-09-26, on the personal machine, read-only)

- **cmux's event stream** (`~/.cmuxterm/workstream.jsonl`) is an append-only stream of agent events with kinds `sessionStart`, `userPrompt`, `toolUse`, `toolResult`, `permissionRequest`, `question`, `stop` and `sessionEnd`, for both Claude Code (38 of 40 rows) and Codex (2, only `sessionStart`). That nearly matches the event vocabulary Moon Base's own hooks use. The session id is encoded in `workstreamId`, and decoded ids joined to a real transcript for 4 of 5 sessions. Rows also carry message content in `payload`, so a reader must not keep it.
- **Claude's own live marker** (`~/.claude/sessions/<pid>.json`) has `status` (`busy` or `idle`) and `statusUpdatedAt`. Moon Base reads the file today only to check the process is alive (`server/harnesses/claude-code.mjs`); the `status` field is unused.
- **cmux's per-session record** (`~/.cmuxterm/claude-hook-sessions.json`) holds only the last hook event per session (`agentLifecycle` running, idle or unknown), so it is coarser than the stream and is not planned as a source.
- The stream held real `permissionRequest` and `question` events from interactive sessions, which is the first real-world evidence for the spec's "permission signals not yet observed" open question, for Claude in cmux.

### Decided in the brainstorm

- **D1. Automatic, visible, easy off.** The cmux source is used whenever its files exist. The Live chip says so ("cmux"), and an env var turns it off.
- **D2. Metadata only.** Moon Base reads event kind, session id, folder and timestamps from cmux's stream, and never keeps or shows the message content in it.
- **D3. Read-only and socket-free.** Nothing is written to cmux or to any tool config, and no cmux socket is needed, so it works when Moon Base was started outside cmux.
- **D4. Layered, with files as the floor.** Signals from cmux's stream, Claude's busy/idle marker and Moon Base's own hooks (where installed) all lay over what the adapters read from files. Every state expires and hands the session back to the next source or to the files, with no error (as AC7 does today).
- **D5. Claude Code first.** Codex is best-effort, wherever cmux reports it; its coverage was thin in what was observed.

### Proposed event mapping (to verify against fixtures)

| cmux kind | Bot state |
|---|---|
| `userPrompt`, `toolUse`, `toolResult` | running |
| `permissionRequest`, `question` | awaiting |
| `stop` | finished |
| `sessionEnd` | forget the session |
| `sessionStart` | no state change |

### Acceptance examples

- **AE1.** At work, with no Moon Base hooks installed, sending a prompt in a cmux Claude session turns its bot to running within the live poll interval (about 3 seconds).
- **AE2.** When Claude asks for a permission the bot shows awaiting. After approval and the tool result it is running again, and at stop it is finished.
- **AE3.** If cmux is not installed, its files are missing or unreadable, or the stream is empty, nothing errors and the files decide.
- **AE4.** With the off switch set, cmux's files are never read and the Live chip does not name cmux.
- **AE5.** An event for a session Moon Base has not scanned is held briefly, then dropped. It never creates a bot (the existing rule).
- **AE6.** Fixture rows containing sentinel message text never reach the page, the API, logs or any file Moon Base writes.
- **AE7.** Unknown kinds or a changed row shape are ignored, the chip shows cmux as not reporting, and the doctor command (slice 4) says why.

## Slice 2. Needs-you view (F2)

One list across every repo of the sessions waiting on you, ordered by how long each has waited. Choosing a row selects that bot, and Open follows the current `Open sessions with` mode. It builds on the awaiting state and the existing next-needing-you key.

- **AE8.** With two repos waiting, both appear, the longer wait first. When one goes back to running it leaves the list within a poll.
- Out for v2: notifications when you are not looking, and approving, denying or nudging a session from the map.

## Slice 3. Insight (F3)

- **I1. What it last said or asked**, on the card, read from the session's transcript. This puts message text on the page, which the hooks deliberately never did, so it needs its own decision (length, opt-out).
- **I2. A "today" timeline per repo:** what started, finished and stalled today, from session files and live events.
- **I3. PR link for CLI sessions,** local only. Claude transcripts already contain `pr-link` entries with the PR number, URL and repository (183 entries in the 9 of 56 recent transcripts that mention a PR). The bot shows "PR #64" with a link. No open, merged or closed state, no GitHub lookups, so AC4 holds and no new process type is needed.
- Cost and token usage stays a non-goal.

## Slice 4. Reach and polish (F4)

- **R1. A doctor command** (through `bin/moon-base.mjs`) that reports what Moon Base can see: tools found, live sources and whether each is reporting, whether `cmux` is on PATH and reachable, hooks status.
- **R2. Easy start:** one command, `moonbase1`, instead of today's `PORT=… MOON_BASE_TERMINAL=cmux npm run dev`, run from a terminal. Always-on start (login item, menu bar) is dropped. Decided 2026-09-26:
  - **The name is `moonbase1`.** Chosen over `starcommand`, which does not say Moon Base and is also the name of Disney's Star Command, at odds with AC9. No collisions were found on this machine's PATH.
  - **One command, with subcommands.** No arguments starts Moon Base. `doctor` (R1) and the existing `install-hooks`, `uninstall-hooks` and `hooks-status` become subcommands of the same command. `npm run moon-base -- <command>` keeps working. Getting `moonbase1` onto PATH takes a one-time `npm link` (nvm keeps that in user space).
  - Behaviors, all four chosen:
    - **Fast.** It serves a ready build so it starts in seconds, and builds only when the build is missing or older than the source.
    - **Auto-detect cmux.** Inside cmux it turns the terminal launcher on by itself. cmux terminals export `CMUX_WORKSPACE_ID`, `CMUX_SURFACE_ID` and `CMUX_SOCKET_PATH` (observed in a process cmux started). Because it runs inside cmux, the launcher's socket rule is met without extra setup. Outside cmux it says the launcher is off.
    - **Free port, opens the page.** It picks a free port when 5274 is taken, or says a copy is already running and reuses that one, then opens the page.
    - **Sensible first-run default.** When the server has a launcher on and the person has not yet chosen an `Open sessions with` setting, the page starts on Terminal instead of Desktop app.
  - An explicit env var or setting still wins over every automatic choice above.
- **R3. Sound, mascot and planet polish,** the deferred delight items.

Acceptance examples for slice 4:

- **AE9.** In a fresh cmux terminal, `moonbase1` starts Moon Base and opens the page, with the terminal launcher on and no env var set. With a build already present it is ready in seconds.
- **AE10.** Run from a normal terminal (outside cmux), it starts fine, says the launcher is off, and copy mode still works.
- **AE11.** With 5274 taken, it starts on a free port. If a Moon Base is already running, it says so and reuses it instead of starting a second server.
- **AE12.** On first load inside cmux, with no stored setting, `Open sessions with` reads Terminal. After the person picks another setting, that choice stays, whatever the server detects.
- **AE13.** The doctor command reports the same detection (inside cmux or not, launcher on or off, port, build fresh or stale).

## Scope Boundaries

Not in v2:

- Approving, denying, nudging or otherwise sending input to a session from the map. It is a v1 non-goal, and the repo's learning is that trust steps stay with the person.
- Notifications outside the page.
- Cost and token analytics.
- GitHub lookups and PR open/merged state.
- More tools, Linux and Windows, and Codex parity at work.
- Writing to cmux or to any tool config.
- Always-on start (a login item or menu-bar app). Dropped 2026-09-26.
- The village or farm theme (see Deferred).

## Success Criteria

- At work, in cmux, with no Moon Base hooks, a session's state change shows within the live poll interval, and "awaiting" appears for the same sessions cmux's own sidebar flags as needing input (checked by hand).
- Someone can tell why a bot is missing or not live from the doctor command alone, without reading code or process lists.

## Constraints and Dependencies

- cmux's stream format is undocumented (`cmux-feed-v1`) and can change between versions. It gets one adapter, fixtures and diagnostics, the same isolation used for the URL schemes.
- Slice 1 depends on cmux's injected hooks firing on the work machine. The user confirmed cmux shows agent status there, but the stream file itself has not been observed there.
- The stream carries message content (D2), so a fixture test with sentinel text is part of the definition of done.
- Observed retention: 40 rows over about 65 minutes in `workstream.jsonl`, 356 rows in `events.jsonl`. Rotation behavior is unknown.
- AC3, AC4, AC5 and AC8 stay as they are for slices 1 to 3.
